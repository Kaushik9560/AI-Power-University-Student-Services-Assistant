# Synthetic data card (Annex E)

| Field | Detail |
|---|---|
| **Purpose** | Test fixture for the University Student Services Assistant. Must exercise: attendance at/below the 80 % threshold, failed/absent/detained results, supplementary clearance, multiple backlogs, CGPA at the placement (6.0) and merit-scholarship (8.5) cut-offs, two programmes and two batches. |
| **Generator** | Claude Fable 5.1 (Anthropic) for the roster via the prompt in `prompts.md`; deterministic Python (`scripts/generate_students.py`, seed 42) for attendance, results and all planted edge cases. 1 generation pass; temperature n/a for the committed data (0.4 when re-run with `--llm` on Ollama). |
| **Prompts** | `data/synthetic/prompts.md` (verbatim). |
| **Schema enforcement** | Pydantic v2 models mirroring Annex C with logical validators (attended ≤ held, total = internal + external, result consistent with marks, ABSENT/DETAINED ⇒ external = 0, reserved id range refused). Invalid rows fail the batch; up to 3 retries; deterministic fallback. `scripts/validate_students.py` re-checks the CSVs independently and is run by the loader before any load. |
| **Row counts and distributions** | 32 students (B.Tech CSE 2024 ×8, CSE 2023 ×8, ECE 2024 ×8, ECE 2023 ×8); 10 courses; 144 attendance rows (78–98 % plus planted values); 97 result rows (85 PASS, 10 FAIL, 1 ABSENT, 1 DETAINED; 1 supplementary PASS). CGPA 5.1–9.2. See `validation_report.txt`. |
| **Edge cases included** | S1001 hero (FAIL in CS201, DBMS attendance 82 %, CGPA 7.21 → placement-eligible once cleared); S1002 DETAINED in CS201 (56 % attendance); S1003 CGPA 5.80 (below placement cut-off); S1004 CGPA 6.00 (exactly at cut-off); S1005 DBMS attendance exactly 80 % (40/50); S1006 one class below (39/50 = 78 %); S1007 FAIL with total 39/100 (one mark below pass); S1008 ABSENT in MA201; S1009 three backlogs and CGPA 5.10; S1010 CGPA exactly 8.50 (merit scholarship cut-off); S1011 FAIL then PASS in supplementary (backlog cleared); S1012 attendance exactly 75 % (old threshold). |
| **Validation results** | `scripts/validate_students.py` → 0 violations (see `validation_report.txt`). Checks: id formats, reserved range, referential integrity, course/programme match, attendance bounds, marks ranges and sums, result–marks consistency, derived vs stored backlogs. |
| **What the LLM got wrong** | In roster generation trials the model (a) reused names, (b) produced CGPAs outside the requested band, and (c) drifted ids outside 1001–1032. All three are caught by the validators and trigger a retry; none reach the CSVs. We deliberately did not let the LLM produce marks or attendance because arithmetic consistency (total = internal + external, result vs pass criteria) failed in early trials. |
| **Known limitations** | CGPA is assigned, not computed from the result rows (so CGPA and marks are not mutually consistent). Only one supplementary session exists. Current-semester courses have attendance but no results. Names are synthetic and do not reflect any real population distribution. Judges' students (S9000–S9999, JDG* courses) are never generated. |
